## 1. The PyMuPDF / AGPL-3.0 question — resolved

**The problem.** `PyMuPDF` (imported as `fitz`) is dual-licensed:
**GNU AGPL-3.0 or a commercial licence from Artifex**. Earlier versions of this
project shipped a PyInstaller specification (`Math Course AI.spec`) that used
`collect_all('fitz')` to fold PyMuPDF's binaries and data **into a distributed
`.exe`**, while the repository root advertised MIT. Distributing that combined binary
creates an AGPL-3.0 derivative whose obligations — including the §13 network-use
source offer — an MIT root licence does not satisfy. **Root MIT does not cancel the
AGPL obligation, and this project does not claim that it does.**

**The decision: drop binary distribution from the public release scope.**

Concretely, in this repository:

| Change | Evidence |
|---|---|
| The PyInstaller spec and the one-command EXE build script are **not present**. | `Math Course AI.spec` and `build_math_course_ai_exe.bat` are absent from the file listing. |
| No binary, wheel, installer or bundle is built, published or attached to a release. | `.github/workflows/ci.yml` runs tests only; there is no packaging or release job. |
| PyMuPDF is **not vendored** and **not installed by default**. It is listed in `requirements-optional.txt`, not `requirements.txt`. | See both files. |
| Every `fitz` import is inside `try/except`, so the program runs without it. | `mca_common.py`, `pdf_viewer.py`, `course_simulation_library.py`, `language_dictionary.py`, `Math_Course_AI.pyw` |

**Why that resolves it.** This project distributes only its own MIT-licensed source.
It does not convey PyMuPDF to anyone. A user who chooses to `pip install pymupdf`
obtains it directly from Artifex/PyPI under Artifex's terms and combines it with this
program **for their own private use**, which the AGPL does not restrict.

**If you want to redistribute a binary of this program that bundles PyMuPDF**, that is
your distribution, and the AGPL-3.0 applies to the combined work: you must offer
complete corresponding source under AGPL-3.0 (and satisfy §13 if you expose it over a
network), **or** obtain a commercial licence from Artifex. Do not rely on this
project's MIT licence to cover it.

Alternatives, if you need PDF rendering without the copyleft: `pypdfium2`
(Apache-2.0 / BSD-3-Clause) and `pdfminer.six` (MIT) cover most of what this program
uses `fitz` for. Migrating is on the roadmap in
[docs/known-limitations.md](docs/known-limitations.md); it has **not** been done, and
this file does not pretend otherwise.

### Fonts

**The published PDF embeds only DejaVu Sans** (DejaVu Fonts License — a permissive,
Bitstream Vera-derived licence that explicitly allows embedding and redistribution).

This took a deliberate change. The editable deck (`tanitim_uret.py` → PPTX/HTML) can
be exported to PDF through Microsoft PowerPoint, but PowerPoint substitutes whatever
font the exporting machine happens to have; a first attempt produced a PDF embedding
subsets of **Verdana**, **Arial** and **Segoe UI Symbol**. Those are Microsoft fonts
whose redistribution depends on their own embedding-permission bits, which is not a
basis this project wants a public artifact to rest on.

The published file is therefore rendered by **`tanitim_pdf.py`**, which draws the same
single-sourced content (`tanitim_icerik.py`) directly to PDF with **matplotlib** and
`pdf.fonttype = 42`. matplotlib bundles DejaVu Sans under the DejaVu Fonts License, so
the output embeds a TrueType subset of a libre font and nothing else. As a side
benefit the published deck no longer needs PowerPoint and can be rebuilt anywhere.

Verified on the published files: the only embedded font programs are
`DejaVuSans`, `DejaVuSans-Bold` and `DejaVuSans-Oblique` subsets.

`tanitim_uret.py` — the *authoring* pipeline — asks for the first available libre
family (**Inter → Source Sans 3 → DejaVu Sans**) and reports honestly when none is
installed. Its PPTX/HTML output is for editing, not for publication.

## 4. Scope of the MIT licence

`LICENSE` is plain, unmodified **MIT** so that automated licence detection reports
it correctly. This section is the scope note that used to be appended to it.

**Covered by MIT:** the source code in this repository (`.py`, `.pyw`, `.ps1`,
documentation, and the output of the embedded question generators).

**Not covered by MIT:**

* **Course material.** Anything you place in your resources folder
  (`Resources/`, `Other Resourceses/`) is third-party copyrighted content and
  separately-licensed open textbooks. It is **not in this repository**
  (`.gitignore`) and is **not** distributed under MIT. Use your own licensed copy.
* **Dependencies.** sympy, matplotlib, NumPy, Pillow, requests, Tesseract and
  especially **PyMuPDF (AGPL-3.0 or commercial)** are governed by their own
  licences. If you distribute a **binary** of this program you must review the
  AGPL terms — see §1. Sharing the source under MIT, as this repository does, is
  unaffected.
* **LM Studio and any language model you run** — governed by their own terms.

## 5. Course material — explicitly excluded

Course PDFs and question banks that a user places in their resources folder are
**third-party content**, are **not** covered by this project's MIT licence, are **not**
in this repository, and are **never** redistributed by it. `.gitignore` excludes the
resources folder. The published screenshots deliberately show only the **synthetic**
demo course tree, never a real catalogue.
